# Lecture notes

## 1. The evolution of NLP

| Approach | Representation | Context | Main limitation |
|---|---|---|---|
| Rules, statistics, n-gram LMs (1990s–2000s) | Words as symbols | n − 1 words | Sparsity; no similarity between words |
| Word embeddings (word2vec 2013, GloVe) | One dense vector per word | None at use time | One vector for all senses ("bank") |
| RNN/LSTM seq2seq (2014), + attention (2015) | Contextual hidden states | Whole sequence in theory | Sequential; long-range information fades |
| Transformer (2017) → BERT/GPT (2018) → GPT-3 (2020) → ChatGPT (2022) | Contextual vectors via attention | Thousands to millions of tokens | Cost with context; hallucination; data hunger |

An **n-gram model** estimates $p(w_t \mid w_{t-n+1}, \ldots, w_{t-1})$ by counting, which is maximum likelihood (the week 1 lab). It fails because most long sequences never occur (sparsity) and because knowledge about *cat* does not transfer to *dog*. Neural language models (Bengio et al., 2003) introduced learned word vectors; **pre-training** on unlabelled text and **fine-tuning** (BERT, GPT, 2018) replaced task-specific models; **scale** enabled **few-shot prompting** (GPT-3); **instruction and preference tuning** produced assistants (ChatGPT, 2022).

## 2. From transformer to LLM: data, scale and context

### The pipeline

1. **Collect** web crawls (e.g. Common Crawl), books, code, maths, papers and multilingual text.
2. **Clean and filter:** de-duplicate (duplicates are memorised), remove low-quality and unsafe text (often with classifiers), remove benchmark test sets (decontamination), balance the mix. Synthetic data generated by other models is increasingly used.
3. **Tokenise** with a trained BPE-style tokenizer.
4. **Pre-train** with next-token prediction on thousands of GPUs for weeks.
5. **Post-train** into an assistant (week 8).

The architecture is last week's decoder transformer, scaled up.

### Compute

$$C \approx 6\,N\,D$$

Training FLOPs ≈ 6 × parameters × tokens (≈ 2 per parameter per token forward, ≈ 4 backward). **Worked example:** $N = 7\times10^9$, $D = 2\times10^{12}$: $C \approx 8.4 \times 10^{22}$ FLOPs. At an effective $4\times10^{14}$ FLOP/s per GPU this is $2.1\times10^8$ GPU-seconds ≈ 58,000 GPU-hours (≈ 1,000 GPUs for 2.5 days). Frontier models use orders of magnitude more, so most organisations adapt existing models rather than pre-train.

### Data scale

GPT-3 was trained on ≈ 300 B tokens (2020), Chinchilla on 1.4 T (2022), Llama 3 on more than 15 T (2024); Hugging Face's open FineWeb dataset contains ≈ 15 T filtered web tokens. One trillion tokens ≈ 750 billion English words.

### Scaling laws

Kaplan et al. (2020) and Hoffmann et al. (2022) found that pre-training loss follows smooth power laws in parameters and data. The Chinchilla fit is

$$L(N, D) = E + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}, \quad E \approx 1.69,\; A \approx 406.4,\; B \approx 410.7,\; \alpha \approx 0.34,\; \beta \approx 0.28$$

For a fixed compute budget the loss is minimised with roughly **20 training tokens per parameter**. GPT-3 (≈ 1.7 tokens/parameter) was under-trained by this criterion. Recent small models are deliberately trained far beyond it (Llama 3 8B: ≈ 1,900 tokens/parameter) because a smaller model is cheaper to serve to millions of users; inference cost, not only training cost, drives design.

![Scaling laws](fig:scaling)

### In-context learning and emergence

Large models can perform a task from a few examples in the prompt without updating weights (**in-context learning**, GPT-3). Some abilities appeared to "emerge" abruptly with scale; Schaeffer et al. (2023) showed that many such jumps reflect discontinuous metrics (exact match), and with continuous metrics improvement is often smooth. Practical rule: test the capability you need at the size you can afford.

### Context windows

The context window (≈ 2 K tokens in 2020; 128 K–2 M in current models) holds the system prompt, conversation, retrieved documents, tool outputs and the answer. Cost and latency grow with context. Models use long contexts unevenly: information in the middle of long inputs is used less reliably ("lost in the middle", Liu et al., 2023). Long context does not remove the need to select relevant information (retrieval, week 12).

## 3. Decoding strategies

| Strategy | Mechanism | Use for | Risk |
|---|---|---|---|
| Greedy | Most likely token each step | Short factual answers, extraction | Loops, bland text |
| Beam search | Keep k best partial sequences | Translation, summarisation with encoder–decoders | Generic output in open chat |
| Temperature | Divide logits by T before softmax | Controlling creativity | High T: errors |
| Top-k | Sample among k most likely tokens | Removing the unlikely tail | Ignores model confidence |
| Top-p (nucleus) | Sample among the smallest set with cumulative probability ≥ p | General chat/writing | Interacts with temperature |
| Repetition penalty | Down-weight used tokens | Long generation | Can corrupt names, numbers, code |

**Worked example (top-p).** Logits [2, 1, 0.5, 0.1, −1] give probabilities [0.56, 0.21, 0.12, 0.08, 0.03]. With $p = 0.8$ the cumulative sums are 0.56, 0.76, 0.89: the nucleus is the first three tokens; the rest are removed and the three kept probabilities are renormalised.

**Real distributions** from the base (pre-trained, not instruction-tuned) Qwen2.5-0.5B model: {{NEXT_TOKEN_NOTES}} Base models are pure next-token predictors: they continue text the way their training data does, so even a factual prefix has many plausible continuations (“located”, “the”, “Dublin”), and the top token “______” reflects the fill-in-the-blank worksheets found on the web. Post-training (week 8) turns this continuation engine into an assistant that answers the question.

## 4. LLM families

### By architecture

* **Encoder-only:** BERT (2018), RoBERTa, DeBERTa, ModernBERT (2024), most embedding models. Masked-language-model pre-training; bidirectional. Use: classification, tagging, embeddings for search. Not a free-text generator.
* **Encoder–decoder:** T5 (2019; Flan-T5 is instruction-tuned), BART, mT5, Whisper (speech). Every task as text-to-text.
* **Decoder-only:** GPT family (OpenAI), Claude (Anthropic), Gemini (Google), Llama (Meta), Gemma (Google, open-weight), Qwen (Alibaba), DeepSeek, Mistral, Phi (Microsoft), OLMo (AI2, fully open with data and code), gpt-oss (OpenAI open-weight, 2025).

### Newer categories

* **Small language models** (≈ 0.1–8 B parameters): run locally or on devices; with good data and distillation they match much larger older models on many tasks.
* **Mixture-of-experts:** many parameters, few active per token (week 5); need memory for all experts.
* **Reasoning models:** trained (usually with reinforcement learning on checkable problems) to produce a long chain of reasoning before answering; spend **test-time compute**. Examples: OpenAI's o-series (2024), DeepSeek-R1 (2025, open), thinking modes in Claude, Gemini and Qwen3. Visible reasoning text is not guaranteed to reflect the internal computation.
* **Multimodal LLMs:** weeks 9–10.

**Real test (thinking off vs on).** An easy word problem and a scheduling puzzle with a hidden constraint (only one 2-GPU run fits on 3 GPUs at a time, so 5 runs take 5 × 4 = 20 hours). {{REASONING_NOTES}}

## 5. Choosing and using models

### Model cards

Check: intended use and out-of-scope uses; training data (sources, languages, dates, personal/copyrighted data); evaluations and settings; limitations and biases; licence and access; technical details (size, context length, tokenizer, chat template, hardware). Missing information is itself relevant for risk assessment (Mitchell et al., 2019).

### Licences

| Type | Examples | Usually means |
|---|---|---|
| Permissive (Apache 2.0, MIT) | Qwen (most), OLMo, Phi, DeepSeek-R1, gpt-oss | Use, modify and commercialise with notices |
| Community/custom | Llama, Gemma | Free use with acceptable-use policies and conditions (Llama: separate licence above 700 M monthly users) |
| OpenRAIL | Stable Diffusion 1.5, BLOOM | Open use with listed prohibited uses |
| Non-commercial research | e.g. SD-Turbo | No commercial use |
| Proprietary API terms | GPT, Claude, Gemini | Pay per use; provider sets data and output terms |

### Benchmarks

| Benchmark | Measures | Caveat |
|---|---|---|
| MMLU / MMLU-Pro | Multiple-choice knowledge | Saturation, contamination |
| GSM8K, MATH | Maths problems | Format sensitivity, memorisation |
| HumanEval, SWE-bench | Code generation; real repository fixes | Narrow languages and tasks |
| GPQA | Hard graduate-level science | Small |
| Human preference arenas | Pairwise votes (Elo) | Style and length bias |

Build a small test set from your own task (week 7) and evaluate shortlisted models with fixed prompts and settings.

### API vs local

Hosted APIs give the strongest models without hardware but send data to a provider, cost per token and may change or retire models. Local/self-hosted open models (Transformers, Ollama, vLLM) give privacy, control and fixed versions and allow fine-tuning, but need hardware and operations. Most providers and local servers accept the same OpenAI-compatible chat format (messages in, message out).

```python
from transformers import pipeline
chat = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B-Instruct")
out = chat([{"role": "user", "content": "Explain tokens in one sentence."}],
           max_new_tokens=60, do_sample=False)
print(out[0]["generated_text"][-1]["content"])
```

```python
from huggingface_hub import InferenceClient
client = InferenceClient(api_key=os.environ["HF_TOKEN"])
resp = client.chat.completions.create(model="Qwen/Qwen2.5-7B-Instruct",
        messages=[{"role": "user", "content": "Name three LLM families."}],
        max_tokens=100, temperature=0.2)
```

### A selection process

Define the task → list constraints (privacy, budget, latency, hardware, licence, languages) → shortlist 2–4 candidates → evaluate on your own test set (quality, cost, latency) → decide, document and re-test when models change. The best model is the smallest, cheapest one that meets the quality bar within the constraints.

# Common misconceptions

| Misconception | Correction |
|---|---|
| "BERT, T5 and GPT are interchangeable chatbots." | Encoder, encoder–decoder and decoder models do different jobs. |
| "Bigger is always better." | Task fit, data, post-training, cost and latency matter; small models often suffice. |
| "Open-weight means open-source and free to use for anything." | Weights ≠ data/code; licences impose conditions. |
| "A top leaderboard score means the model is best for my task." | Benchmarks can be contaminated or saturated; test on your own data. |
| "A million-token context means retrieval is unnecessary." | Cost, latency and lost-in-the-middle effects remain. |
| "Reasoning models show their true reasoning." | Visible reasoning may not be faithful; check answers. |
| "Temperature 0 makes an API perfectly reproducible." | Server-side changes and non-determinism can still alter outputs. |

# Responsible AI lens: large language models

* **Data provenance and copyright:** limited disclosure of training data; ongoing litigation.
* **Bias:** stereotyped outputs (e.g. BERT's gendered predictions in the lab) and unequal quality across languages and dialects.
* **Hallucination and overconfidence:** fluent answers without guarantees.
* **Privacy:** memorisation of training data; data sent to APIs.
* **Openness:** open weights support scrutiny and local control but also misuse; the EU AI Act adds obligations for general-purpose AI model providers.

# Practice questions with model answers

## Multiple choice

1. Chinchilla's scaling result suggests, for a fixed compute budget: **(a)** as many parameters as possible; **(b)** about 20 tokens per parameter; **(c)** 1 token per parameter; **(d)** no dependence on data. *Answer: (b).*
2. Training compute is approximately: **(a)** N + D; **(b)** 6ND; **(c)** N²D; **(d)** 2N/D. *Answer: (b).*
3. Which model family generates free text left to right? **(a)** BERT; **(b)** RoBERTa; **(c)** decoder-only models such as Llama; **(d)** embedding models. *Answer: (c).*
4. Top-p sampling with p = 0.9: **(a)** keeps 90% of tokens; **(b)** keeps the smallest set of tokens with cumulative probability ≥ 0.9; **(c)** sets temperature to 0.9; **(d)** keeps the 9 most likely tokens. *Answer: (b).*

## Short answer

1. **Estimate the training compute for a 1 B-parameter model trained on 100 B tokens.** (2 marks) *Model answer:* 6 × 10⁹ × 10¹¹ = 6 × 10²⁰ FLOPs.
2. **Explain why modern small models are trained on far more than 20 tokens per parameter.** (3 marks) *Model answer:* Chinchilla optimises training compute only; deployed models serve many requests, so a smaller model trained longer reaches the required quality with lower inference cost and latency.
3. **Compare BERT, T5 and GPT on architecture, pre-training objective and typical use.** (6 marks) *Model answer:* encoder / masked LM / classification and embeddings; encoder–decoder / span corruption text-to-text / translation and summarisation; decoder / next-token / generation and chat (2 each).
4. **Give two reasons to be cautious about leaderboard scores.** (2 marks) *Model answer:* contamination, saturation, prompt/format sensitivity, mismatch with your task, style bias in human votes.

## Exam-style question

**"A hospital wants an assistant that summarises patient discharge letters. Discuss how you would choose an LLM, covering model families, open vs proprietary access, size, decoding settings, evaluation and responsible-AI considerations."** (20 marks)

*Marking guide:* task definition and constraints including privacy/GDPR (4); family and size justification, e.g. a decoder LLM or encoder–decoder summariser, preferring locally hosted open weights (4); decoding choice for faithful summaries (low temperature/greedy or beam) (3); evaluation plan on a de-identified test set with factual-consistency checks and clinician review (5); responsible AI: hallucination risk, bias, licence, audit trail, human oversight (4).

# Glossary

| Term | Meaning |
|---|---|
| n-gram model | Predicts the next word from the previous n − 1 words by counting |
| Word embedding | Dense learned vector per word |
| Pre-training | Self-supervised training on large unlabelled text |
| Scaling law | Empirical power law relating loss to parameters, data and compute |
| Chinchilla optimum | ≈ 20 training tokens per parameter for fixed compute |
| In-context learning | Performing a task from examples in the prompt without weight updates |
| Context window | Maximum tokens the model can attend to in one call |
| Beam search | Decoding that keeps the k most probable partial sequences |
| Top-p (nucleus) | Sampling from the smallest set of tokens with cumulative probability ≥ p |
| Open-weight model | Model whose weights are downloadable under a licence |
| Small language model | Model of roughly ≤ 8 B parameters for local or device use |
| Reasoning model | Model trained to generate extended reasoning before answering |
| Test-time compute | Extra inference computation (e.g. thinking tokens) to improve answers |
| Model card | Documentation of a model's intended use, data, evaluation, limits and licence |
| Contamination | Benchmark test data appearing in training data |
