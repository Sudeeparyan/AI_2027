



The Core Problem & What MCP Is
The Problem MCP Solves
	• If you build an AI application, your model needs to talk to your database, CRM, file system, or Slack.
	• Every single one of those connections requires a custom integration that you have to write, test, and maintain.
	• Scaling up to 10 applications and 100 tools creates potentially 1,000 different custom integrations.
	• Analogy: It is like the drawer of chargers we all had before USB-C—one cable per device, with none of them being interchangeable.
What is MCP?
	• MCP (Model Context Protocol) is the USB-C for AI.
	• Originally released by Anthropic in November 2024, it is an open standard that provides one common language for connecting AI models to external tools and data.
	• You build a connector once, and any MCP-compatible AI application can use it (Claude, ChatGPT, Cursor, or a custom agent) without rewriting code.
	• In December 2025, Anthropic donated MCP to the Linux Foundation, turning it into a vendor-neutral, community-governed standard.


How MCP Works Under the Hood (The 3 Core Pieces)
Continuing the USB-C analogy, MCP consists of three main components:



1. The Host
	• The AI application itself (e.g., Claude Desktop, Cursor, VS Code, ChatGPT).
	• Analogy: Think of the host as your phone.
2. The MCP Client
	• Lives inside the Host.
	• Speaks the protocol and manages the connection (you rarely need to see it).
	• Analogy: Think of it as the USB-C port on the phone.
3. The MCP Server
	• The accessory that you plug in.
	• A small program that wraps a tool or data source (database, calendar, GitHub) and exposes it in the standard MCP format.
	• Analogy: Think of it as the USB-C accessory/cable you plug into the port.
	• Can literally be 100 lines of Python code running locally on a laptop.





What an MCP Server Provides
An MCP Server exposes three primitives:
	• Tools: Software access given to the model so it can take actions (what the model can do). Like office laptop
	• Resources: Data sources or internal pages given to the model so it can read what it needs (what the model can read). Like when I joined project the confluence page
	• Prompts: Standard operating procedures or reusable templates for performing common tasks well. Like the DDD princeples the process that I need to fallow.
The Runtime Discovery Process
	• When the Client connects, it asks the Server: "What do you have?"
	• The Server advertises its tools, resources, and prompts along with descriptions and typed inputs.
	• Everything is discovered at runtime; nothing is hardcoded.
Where MCP Sits Inside an AI Agent Architecture


MCP alone is not an agent. Inside an AI Agent, a harness runs a loop around the model:
[ Model (Brain) ] <---> [ Agent Harness (Workstation/Workflow) ] <---> [ MCP Client ] <---> [ MCP Server (External Systems) ]
	• The Model: Acts as the brain that does the reasoning.
	• The Harness: Acts as the workstation/workflow. Manages memory, tracks state, controls the loop, and handles execution in the real world.
	• MCP: Acts as the company badge—the standardized access layer that gets the agent into every system it is allowed to touch.


Execution Loop Step-by-Step
	1. The Model decides it needs an external resource (e.g., pulling rows from a database).
	2. The Harness routes that intent through an MCP Client to the right MCP Server.
	3. The MCP Server performs the actual work.
	4. The result flows back into the Model's context so it can continue reasoning.
	Summary: Model decides, Harness executes, MCP connects.
Technical Comparisons: Clearing Up the Myths
1. MCP vs. Function Calling
	• Function Calling: A capability of the model. The model looks at a task, decides a tool is needed, and produces a structured request with arguments ("Should I make a call, and what should I send?").
	• MCP: The protocol that carries that request to the tool and brings the result back ("How does that call reach the other end?"). 
	• Analogy: Function calling is deciding to call someone and dialing the number. MCP is the telephone network that connects any phone to any other phone. They are complementary layers.

2. MCP vs. Plain APIs
	• APIs: Point-to-point connections to single services. APIs do the actual underlying work.
	• MCP: A standardized layer built on top of your APIs that enables an AI model to discover and invoke them consistently. It does not replace APIs.
3. MCP vs. Plugins
	• Plugins (2023 Era): Proprietary integrations tied to specific platforms (e.g., ChatGPT Plugins). Building a plugin for one platform required rebuilding it for another. (The old charger model).
	• MCP: Flips the model to a single open protocol. You build an MCP server once, and it works across Claude, ChatGPT, Cursor, VS Code, and custom agent frameworks.
Where to Find & How to Run MCP Servers
3 Primary Places to Find Servers
	1. Official MCP Registry: The canonical dictionary where verified publishers list their servers.
	2. Model Context Protocol Servers Repository (GitHub): Contains reference servers for file systems, fetch, memory, etc.
	3. Community Directories: Directories like Pulse MCP for browsing by category (PostgreSQL, GitHub, Notion, etc.).
Local vs. Remote MCP Servers
Feature	Local MCP Server	Remote MCP Server
Execution	Runs directly on your machine	Hosted externally on a server/cloud
Transport	stdio (Standard Input/Output process communication)	HTTP / WebSockets
Auth	Direct local process execution	OAuth / Token Authentication
Use Cases	Local files, local development, experimentation	Enterprise products, shared cloud services
How to Use an MCP Server
	1. Add a small configuration entry in your host client (Claude Desktop, Cursor, or VS Code) specifying either the launch command (for local stdio) or the URL (for remote HTTP).
	2. Restart the client; it handles the handshake and discovers the tools automatically.
Security & Production Best Practices
An MCP Server gives code a direct line into your AI’s context, accounts, and data.
Known Security Threats
	• Tool Poisoning Attacks: Malicious instructions hidden inside tool descriptions.
	• CVEs & Vulnerabilities: Path traversal vulnerabilities in unverified hosting platforms exposing application environments.
Practicioner’s Security Checklist
	1. Source Code Audit: Prefer official servers from verified publishers or read the code before running it.
	2. Principle of Least Privilege: Pass read-only credentials if the server only needs read access.
	3. Human-in-the-Loop: Keep human approval required for sensitive/irreversible operations (writes, deletes, sending messages).
	4. Enterprise Architecture Pattern: Place internal MCP servers behind a central gateway or internal registry with scoped read-only credentials by default.
How to Build Your Own MCP Server in 15 Minutes
Stack & Tools
	• SDKs: Official Python SDK (featuring FastMCP) or the official TypeScript SDK.
	• Testing Tool: MCP Inspector (a local web interface to trigger and debug tools manually before connecting them to an LLM).
Implementation Steps (Python)
	1. Write a normal Python function using standard type hints and a docstring.
	2. Apply the FastMCP decorator (@mcp.tool()) over the function. The SDK automatically converts it into a fully described MCP tool.
	3. Test and validate inputs using the MCP Inspector.
	4. Add the execution script to your client configuration file over stdio.
	5. Connect to HTTP / OAuth only when scaling to multi-user requirements.

Introduction & Motivation
	• The Infrastructure Gap: While everyone talks about building AI agents and RAG (Retrieval-Augmented Generation) systems, very few focus on the core backend infrastructure that makes it all possible: Vector Databases.
	• Significance: Understanding vector databases bridges the gap between basic LLM concepts and building real-world enterprise AI applications (e.g., semantic search, memory-augmented systems, and recommendation engines).
Level 1: The Problem with Traditional Databases
Keyword vs. Meaning-Based Matching
	• Traditional Databases (Relational / SQL):
		○ Examples: MySQL, PostgreSQL.
		○ Mechanism: Designed for exact or partial string matching (e.g., WHERE text LIKE '%vacation%').
		○ Limitation: Fails when the query lacks exact keywords. For instance, if a user asks "How many days off do I get per year?", a SQL query searching for "vacation" will return zero results, even if the policy document answers the query directly.
	• Vector Databases:
		○ Mechanism: Built for meaning-based (semantic) matching.
		○ Value Proposition: Understands that "days off" and "vacation" refer to the same underlying concept, retrieving relevant records based on semantic similarity regardless of wording.
Level 2: What is a Vector / Embedding?
1. Human Meaning vs. Machine Representation
	• Human Cognitive Model: When humans hear a word like "king", the brain does not just store the four characters k-i-n-g. It stores a web of contextual associations—royalty, power, leadership, crowns, and governance.
	• Embeddings (Vectors):
		○ Machine learning models convert data (words, sentences, images, audio, PDFs) into a dense array/list of floating-point numbers called a vector or embedding.
		○ These numbers position concepts inside a high-dimensional vector space where distance corresponds to semantic similarity.
2. Vector Arithmetic & Dimensions of Meaning
	• Vector Geometry: Vectors with similar meanings land close together in mathematical space.
	• Classic Semantic Vector Math:
$$\text{Vector("King")} - \text{Vector("Man")} + \text{Vector("Woman")} \approx \text{Vector("Queen")}$$
	• Takeaway: Embeddings capture abstract dimensions (such as gender and royalty) as navigable mathematical properties rather than arbitrary text strings.
Level 3: RAG & Document Chunking Strategies
1. The RAG Analogy
	• Closed-Book Exam (Raw LLM): An LLM operating without RAG relies exclusively on static parametric memory learned during training. It cannot answer questions about private enterprise data or events post-dating its training cutoff without hallucinating.
	• Open-Book Exam (RAG System):
		○ LLM = Student with strong reasoning capabilities.
		○ Vector Database = Open textbook providing precise reference material.
		○ The LLM flips to the relevant document chunks retrieved by the vector database and formulates grounded answers.
2. RAG End-to-End Pipeline
	1. Ingestion & Embedding: Ingest documents $\rightarrow$ chunk them $\rightarrow$ pass chunks through an embedding model $\rightarrow$ index generated vectors in a Vector Database.
	2. Query Processing: User submits a natural language prompt $\rightarrow$ prompt is converted to a query vector using the same embedding model.
	3. Vector Retrieval: Database performs a similarity search and retrieves top-$k$ nearest context chunks.
	4. Augmentation & Generation: System injects retrieved chunks into the context window alongside the prompt $\rightarrow$ LLM generates a grounded response.
[ Raw Documents ] ---> [ Semantic Chunker ] ---> [ Embedding Model ] ---> [ Vector DB ]
                                                                             │
                                                                             │ Top-k Context
                                                                             ▼
[ User Prompt ] ------> [ Embedding Model ] ---> [ Similarity Search ] ──> [ Context Window ]
                                                                             │
                                                                             ▼
                                                                        [ LLM Brain ]
                                                                             │
                                                                             ▼
                                                                     [ Grounded Answer ]

3. Document Chunking Best Practices
	• Chunk Size Trade-Offs:
		○ Too Large: Loses precision; injects irrelevant noise into the context window.
		○ Too Small: Loses essential surrounding context, degrading reasoning quality.
	• Baseline Benchmark:
		○ Size: $300 - 500$ tokens per chunk.
		○ Overlap: $50 - 100$ tokens of sliding boundary overlap to prevent loss of information at cutoffs.
	• Methodology: Prefer Semantic Chunkers (which split text along logical boundaries and sentence meanings) over simple fixed-character splitters.

Level 5: Broader Real-World Use Cases
Vector databases extend far beyond text retrieval in RAG pipelines:
	• Recommendation Systems:
		○ Spotify: Converts user listening history and audio characteristics into vectors to perform nearest-neighbor searches across catalog song vectors.
		○ Netflix: Matches user preference profiles to movie/show vector embeddings.
	• Multimodal & Visual Search:
		○ Pinterest: Converts images into vectors via computer vision models to perform visual similarity searches (e.g., finding matching furniture from a photo).
	• Cybersecurity & Anomaly Detection:
		○ Normal network traffic patterns cluster together within a specific vector subspace.
		○ Outlier vectors falling far from established clusters trigger real-time anomaly alerts.
